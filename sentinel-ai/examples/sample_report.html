Hardcoded JWT Secret Key in Application Configuration (Synthetic) High
Asset: 192.168.1.10:8080/app/config.py CWE: CWE-798 Confidence: Confirmed

Static analysis detected a default weak HMAC secret ('change-this-to-a-random-secret-key') used to sign authorization tokens. (Synthetic laboratory finding).

Remediation:

Generate a cryptographically secure random key with at least 256 bits of entropy and supply it via an environment variable or secrets manager.

Cross-Site Scripting (Reflected XSS) in Error Page (Synthetic) Medium
Asset: 192.168.1.10:8080/error.html CWE: CWE-79 Confidence: Confirmed

User-supplied error parameter is reflected in the HTML response without HTML entity encoding or Content-Security-Policy restrictions.

Remediation:

Apply contextual output encoding using standard templating engines with auto-escaping enabled and implement a strict Content-Security-Policy (CSP) header.

Remediation Priorities

  1. Immediate (P0): Remediate SQL injection on search endpoint (CWE-89) by implementing parameterized SQL queries.
  2. Immediate (P1): Rotate JWT signing secret in configuration (CWE-798) and inject via environment variable.
  3. High (P2): Implement context-aware HTML entity encoding on error pages (CWE-79) and deploy CSP header.
  4. Medium (P3): Deploy standardized defense-in-depth HTTP security headers (HSTS, CSP, X-Content-Type-Options).
  5. Low (P4): Suppress web server banner version disclosure in production web server configuration.
